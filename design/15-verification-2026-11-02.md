# 追加変更後の試験記録

2026-11-02の「試験を実施してください」に基づき、XInputの差分修正、4軸ヒストグラム、Python旧ファイル削除を含む現行コードを検証した。macOS 14.6.1 ARM64、.NET SDK 10.0.403 / runtime 10.0.14。Windowsネイティブ入力・WPF実行の受入結果ではない。

## 復元・ビルド・回帰試験

全16プロジェクトのlock付き復元とクロスビルドが成功し、警告0・エラー0。WPF本体・試験を含めてコンパイルした。回帰試験は次の161ケースすべて合格、失敗0・スキップ0。

| 対象 | 合格数 |
| --- | ---: |
| Core | 82 |
| HID直接のモック／デコード | 21 |
| XInputモック | 14 |
| Application統合・設定 | 31 |
| CLI・CSV | 13 |

追加26ケースは、ヒストグラムのbin丸めと境界、無効差分、両端が30秒以内という条件、欠測・epoch・保持上限・過去時計、微小差分、immutableな結果、4軸合算、無受信での失効、表示参照での二重計数防止、リセット／モード変更／切断を確認する。増分結果を参照窓の全差分から独立に計算した分布と比較した。XInputのpacket 0→8→16を通常・低遅延の両モードで試し、全4軸の推定値と分布、非連番診断を確認した。

初回の追加統合試験は、10Hzの解析後に時計を1msだけ進めて更新を期待したため1件失敗した。試験の時刻を100ms間隔へ修正し、Application全31ケースを再実行して合格した。本体の実装変更はない。初回ログと最終TRXを両方保存し、初回の失敗を最終合格に混ぜていない。

## 300秒相当の仮想負荷

4軸、解析10Hz、各300秒。量子化、signed 16bit乱数、量子化／乱数／状態不変の混在、全観測でcontinuityを変えるfragmentedの4パターンを100／1,000／8,000Hzで実行した。各条件3,000回の解析。Release実行とビルド／回帰試験は直列。

| パターン | Hz | 解析p95 ms | 解析p99 ms |
| --- | ---: | ---: | ---: |
| 量子化 | 100 | 0.308 | 1.237 |
| 量子化 | 1,000 | 0.543 | 1.408 |
| 量子化 | 8,000 | 0.357 | 1.490 |
| 乱数16bit | 100 | 0.361 | 2.397 |
| 乱数16bit | 1,000 | 5.519 | 12.351 |
| 乱数16bit | 8,000 | 0.630 | 36.008 |
| 混在 | 100 | 0.237 | 0.704 |
| 混在 | 1,000 | 0.410 | 4.049 |
| 混在 | 8,000 | 0.353 | 21.857 |
| 毎回欠測境界 | 100 | 0.665 | 2.693 |
| 毎回欠測境界 | 1,000 | 0.851 | 16.065 |
| 毎回欠測境界 | 8,000 | 0.509 | **158.960** |

12条件すべてで取得上限による切捨てはなく、原データ保持期間と描画投影期間の差の最大値は0秒。原データは軸ごと最大240,001点、描画は8,192点以内。これは内部の点省略や実機の欠落が0という意味ではない。ヒストグラム件数が保持隣接対数を超えないこと、量子化入力では全非ゼロ差分を数えること、毎回欠測境界では0件となることを全解析で検査した。

**8kHz毎回欠測境界は性能目標未達**。p99は約159msで、[07の100ms未満の目標](07-performance.md)を超えた。解析最大約193ms、終了時の明示GC後の生存ヒープ約566MiB、GC停止合計約18.46秒／実測約26.61秒。GCには計測用の明示GCも含むため、その比率を本番運転の停止率として扱わない。大量の区切りを短時間に生成する条件であり、実際のWindows GC停止の原因・時間をこの測定だけで断定しない。

保持点・投影期間・分布が正しくても性能を受入済みとはしない。区切りごとの投影オブジェクト保持とGCを次の調査対象とする。Windows ETW等で照合し、compactな値型ストレージや再利用による割当削減を検討する。最新30秒の端点・極値と欠測境界を維持したまま、同じ300秒負荷と実時間試験でp99・最大停止・生存ヒープを再評価する。

仮想時刻は待機せず進めるため、割当は実時間に圧縮される。解析時間にはヒストグラムのsnapshot生成を含み、追加／失効は別のappend計時に含む。WPF描画・実ドライバー・USB・Windowsタイマーは含まない。初回と定常の混在やGCタイミングによりp95とp99は大きく異なり、単発値からハードウェア性能を推測しない。

## 実時間5分の取得・解析モック

XInputモック→本体Controllerを通常／1ms設定で300.03秒動かし、17msごとに表示スナップショットを参照した。実測状態更新は平均約782Hzで、1,000Hzの実機動作を保証する試験ではない。

- 解析2,944世代を観測し、p95 4.616ms、p99 20.337ms、最大23.646ms。
- 40秒以降の5秒区間の割当量は8.69〜9.03MiB/秒。終了時ヒープ約130.4MiBは明示GC前の値で、生存メモリ量の推定には使わない。
- 5秒ごとのキュー観測は最大4件・最古約3.85ms。観測した範囲で時間とともに増える滞留はない。サンプリング間の一時的な最大値や破棄0までは断定しない。
- 40秒以降の4軸合算ヒストグラムは約92,839〜94,415件で、各観測の保持隣接対数の上限以内。分布の件数は表示のポーリング回数に依存しない。
- 全CPU比は40秒以降の区間で約1.81〜2.36%。GC停止合計約2.33秒。個別停止のp99はこの計測器では取得していない。

通常条件の解析と割当量は設計目標内だが、WPFを含むGUI全体の目標達成を意味しない。10分以上のWindows連続運転も未実施。drainの百分位は末尾10,000計測、解析は観測した全2,944世代に基づく。表示参照で見逃した解析世代を補間しない。

## 配布物・削除後の整合性

GUIは389件、CLIは182件の収録ファイルを全てビルド元のSHA256と照合した。ネイティブhostの内容もbundle位置以外が一致し、GUI／CLI各ディレクトリは単一EXEのみ。ヒストグラム実装時の配布EXEと同じSHA256で、本体の再生成や修正は不要だった。これはWindowsでの実行試験ではない。

lock16件は試験前後で一致。Python旧版の削除対象7パスは全て存在せず、保持したCSV22件とfixture1件のSHA256は削除前と一致した。最新設計とこの試験記録を配布ZIPへ反映し、manifest・ZIP内容のSHA256を照合する。
