# 機能・計算仕様 v2（C# / Raw Input）

C#版の正本。Python v1の過去の計測仕様は[旧仕様](../python-v1/01-specification.md)を参照。Raw Inputによる入力意味の変更を含む。

## GUI

初期サイズは1280×900程度を目安とし、DPI拡大とリサイズに追従する。上部にデバイス選択、接続状態、計測時間、実測の受信レポートレート・軸別サンプルレート、リセットを配置する。左右に同じ大きさのパネルを並べ、各パネルの上部に大きな円形の位置表示、下部に精度、震え統計、時系列グラフを置く。小画面ではスクロール可能にする。

円の中心を(0,0)、半径を1とし、十字軸と目盛りを描く。点とX/Y数値を同時表示する。生の各軸は[-1,1]、画面は右が+X、下が+Yとし、HID軸の向きは割当・反転で合わせる。描画座標は `cx + R*x, cy + R*y`。四隅の入力では円の外になるため、円を含む[-1,1]四角領域を確保し、点を円周へ投影しない。解析は描画用の座標変換や間引きに影響されない。

未接続時は点を非表示にし「未接続」、推定できない値は「—」と理由を表示する。0bit、無限大、NaNを代替表示しない。接続直後から値を表示し、30秒未満は「収集中: n.n / 30.0秒」を表示する。30秒待つ開始ボタンや準備待機は設けない。

M3でHID Usage/Report ID/Link Collectionに基づく軸候補と割当・反転を用意する。M4で左右表示へ統合し、M6で設定を永続化する。機種の違いを軸インデックス0〜3に固定しない。詳細は[取得設計](05-raw-input.md)。

## サンプルと30秒窓

- 時刻は単調増加クロック `Stopwatch.GetTimestamp()`と`Stopwatch.Frequency`。時計変更の影響を受けない。解析では秒へ変換可能。
- 各受信レポートから、そのレポートが含む軸だけのサンプルを生成し、軸別の受信時刻t・順序・連続性IDを持つ。4軸を埋めるために前回値を複製しない。異常値（非有限値、範囲外、Null等）は破棄し、当該軸の次の有効サンプルとの間で差分を作らない。
- 現在時刻Tで `T-30 <= t <= T` のサンプルを採用する。描画や解析が呼ばれた時も期限切れを削除し、最後のサンプル時刻を窓の終端にしない。
- 差分は同一セッションの連続サンプル間でのみ作る。前後両方のサンプルが現在の窓内にあること。差分の後端だけが窓内でも採用しない。
- サンプル1個でも平均は表示でき、母標準偏差と平均からの最大偏差は0。ただし「1サンプル」を併記する。0個では全統計を「データなし」とする。
- デバイス変更、切断、再接続、軸割当変更、リセットでセッションを更新し履歴を破棄する。アプリ内で既知のレポート破棄、無効値、パース失敗を差分の不連続境界とする。別Report IDに属していて今回含まれない軸は欠測とみなさない。Raw Inputの無受信100msだけでは不連続としない。長い間隔を埋める補間・複製はしない。
- バッファ上限は軸別300,000サンプル。8kレポート/秒の合成負荷で30秒を保持できる量とする（実機レートを保証するものではない）。上限超過で窓内データを失った場合は警告と実際の保持時間を表示し、完全な30秒計測と扱わない。

## ステップ精度: 最頻差分方式 v1

各軸に対して次の順に処理する。

1. 窓内の隣接サンプルについて `d = abs(current - previous)` を計算する。
2. `d == 0` を除く。同じ値のレポートの再受信はゼロ差分になるため、ステップの候補としない。非ゼロの微小値は勝手にノイズ扱いして除外しない。
3. 浮動小数点の表現差を吸収するため `q=0.0000001` の固定幅でバケット化する。キーは `floor(d/q + 0.5)` とし、キー0は推定に使わず除外件数を表示する。qはversion付き設定として保持し、設定変更で履歴を再評価する。初期q以下の差分には分解限界があることをヘルプに示す。
4. キーごとの件数が最大のバケットを選び、その中の元のdの算術平均を基本ステップ差sとする。複数バケットが同率最大なら小さいキーを選び、「最頻値が同率」と表示する。時間順序によって結果を変えない。
5. 有効な非ゼロ差分が1個あれば暫定推定を返す。初期方針として30個未満は「参考値」を付ける。30個以上でも最頻割合と件数を併記し、精度保証とはしない。
6. `levels = 2.0 / s`、`bits = log2(levels)`。levelsを先に整数化しない。表示だけを小数1桁で四捨五入する（C#の`Math.Round(value, 1, MidpointRounding.AwayFromZero)`。非負bit値に対して四捨五入とし、decimalでの8.05→8.1も試験する。既定の偶数丸めは使用しない）。内部のs、levels、bitsは丸めず保持する。

| s | levels | bit表示 |
| --- | --- | --- |
| 0.0078125 | 256 | 8.0bit |
| 0.00390625 | 512 | 9.0bit |
| 0.001953125 | 1024 | 10.0bit |
| 0.0009765625 | 2048 | 11.0bit |
| 0.003 | 約666.667 | 9.4bit |

s=0、非有限値、(0,2]の範囲外は無効。非ゼロ差分がないときは「変化なし／ゆっくり動かしてください」。高速操作で複数のハードウェア段階を飛ばす場合、最頻差分が基礎分解能と一致しないことがある。表示名は「推定ステップ精度」とし、公称bit数とは区別する。

スティック代表値は `min(bits_x, bits_y)` を丸めて表示し、X/Yを別途表示する。一方が無効なら代表値は「—（XまたはY未計測）」とする。片軸の値を両軸の結果として扱わない。手法名、基本ステップ差、段階数、非ゼロ件数、最頻割合、同率状態も詳細欄で確認可能にする。

## 震え度合い

各スティックのX/Yを別々に計算する。対象は現在の窓内の全有効サンプル（変化ゼロを含む）。平均 `mu = sum(v)/N`、母分散 `sum((v-mu)**2)/N`、母標準偏差 `sigma = sqrt(variance)`。旧Python版と同じ母標準偏差（分母N、ddof=0相当）とする。平均からの最大偏差は最大絶対偏差 `max(abs(v-mu))` とする。左右それぞれのX/Y軸について、「標準偏差」「平均」「平均からの最大偏差」の3指標を震え統計欄に並べて常時数値表示する。3指標はすべて同じ最新30秒窓（30秒未満では取得済みの範囲）から計算する。標準偏差を差分列から計算しない。

左右それぞれにX/Yの2波形を表示する。横軸は現在を0、30秒前を-30とする固定表示、縦軸は[-1,1]。現在の平均線と±sigma帯を軸別に表示し、色に加えて凡例と線種で識別する。別々のグラフまたは切替表示で帯が識別できること。拡大表示を付ける場合も倍率を明記する。欠落区間は線で結ばない。直近の標準偏差・平均・平均からの最大偏差の3指標に加えて、サンプル数・保持時間も数値で示す。

描画は横方向の表示幅に応じたmin/max間引きを使用し、短い揺れの山谷を保つ。計算には全サンプルを使う。意図した移動、ドリフト、ノイズはすべて位置のばらつきに含まれるため、静止して測る説明を画面に置く。

## Raw Inputへの変更と比較の条件

受信イベント駆動で、固定1,000Hzの再サンプリングは行わない。同一時刻の複数レポートを受信順で保持し、時刻が同じという理由だけで破棄しない。時刻逆転は拒否する。ウィンドウ境界は受信時刻で判定し、軸ごとにサンプル数と保持期間を表示する。

震えの3指標は**受信サンプルを等しい重み**で計算する。値の変化時だけレポートが来る機器では、一定周期で測るPython版の統計と分布が変わる。時間重み付き統計や補間は初期版では追加しない。方式を追加する場合は名称と計算規則を別にする。

30秒以内に有効値がなければ統計は「データなし」。静止時の無受信を切断と断定せず、最後に受信した位置を示すときは「最終受信値」と年齢を付ける。X/Yが別レポートならそれぞれの年齢も確認できる。

HIDのBitSizeは格納幅であり、推定ステップ精度と別の情報。正規化は論理min/maxへの単一の線形変換とし、元整数値を保持する。例えば0..255ではstep=2/255、段階数255、約8.0bitとなる。結果を256に合わせるための補正はしない。

言語間の移植一致は、同じ正規化値・時刻・連続性を持つfixtureで比較する。実機のpygameポーリング値とRaw Inputイベントの時系列が同一になることは受入条件にしない。
