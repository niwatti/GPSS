# 機能・計算仕様 v3（C# / HID直接読み取り・XInput）

C#版の正本。旧Python版の文書・ソースはユーザー指示により削除し、移植時の比較fixtureは現行C#試験用に保持する。HID直接読み取りとXInput状態取得による入力意味の違いを含む。

## GUI

起動時はWindowsの作業領域へ最大化し、1920×1080でスクロール不要な配置とする。DPI拡大とリサイズに追従する。上部に取得方式（HID直接 / XInput）・取得モードの固定表示・デバイス選択、接続状態、計測時間、方式別の実測レート、リセットを配置する。HIDは受信レポート/秒、XInputは状態更新検出/秒とAPI呼出し/秒を示し、軸別サンプル/秒も確認可能とする。左右に同じ大きさのパネルを並べ、各パネルの上部は大きな円形の位置表示と精度情報を横並び、下部は震え統計と時系列グラフとする。表示領域が小さい場合は全体を同じ比率で縮小する。詳細は[08](08-desktop-layout.md)を参照。

円の中心を(0,0)、半径を1とし、十字軸と目盛りを描く。点とX/Y数値を同時表示する。生の各軸は[-1,1]、画面は右が+X、下が+Yとし、HID軸の向きは割当・反転で合わせる。描画座標は `cx + R*x, cy + R*y`。四隅の入力では円の外になるため、円を含む[-1,1]四角領域を確保し、点を円周へ投影しない。解析は描画用の座標変換や間引きに影響されない。

未接続時は点を非表示にし「未接続」、推定できない値は「—」と理由を表示する。0bit、無限大、NaNを代替表示しない。接続直後から値を表示し、選択期間W秒に満たない場合は「収集中: n.n / W.0秒」を表示する。W秒を待つ開始ボタンや準備待機は設けない。

M3でHID Usage/Report ID/Link Collectionに基づく軸候補と割当・反転を用意する。M4で左右表示へ統合し、M6で設定を永続化する。機種の違いを軸インデックス0〜3に固定しない。詳細は[取得設計](05-input-acquisition.md)。

## サンプルと選択期間の窓

Wは10／30／60／300秒から選択し、未設定時は30秒。平均精度・ヒストグラム・震え・波形へ共通に適用する。変更時は履歴をリセットし、選択を保存・復元する。[17](17-measurement-window-selection.md)参照。

- 時刻は単調増加クロック `Stopwatch.GetTimestamp()`と`Stopwatch.Frequency`。時計変更の影響を受けない。解析では秒へ変換可能。
- HIDは各受信レポートが含む軸だけ、XInputは初回とpacket番号更新時の状態が含む軸のサンプルを生成し、軸別の受信時刻t・順序・連続性IDを持つ。4軸を埋めるために前回値を複製しない。異常値（非有限値、範囲外、Null等）は破棄し、当該軸の次の有効サンプルとの間で差分を作らない。
- 現在時刻Tで `T-W <= t <= T` のサンプルを採用する。描画や解析が呼ばれた時も期限切れを削除し、最後のサンプル時刻を窓の終端にしない。
- 差分は同一セッションで実際に取得できた隣接する有効サンプル間で作る。XInputのpacket番号が非連番でも、それだけで差分を除外しない。前後両方のサンプルが現在の窓内にあること。差分の後端だけが窓内でも採用しない。
- サンプル1個でも平均は表示でき、母標準偏差と平均からの最大偏差は0。ただし「1サンプル」を併記する。0個では全統計を「データなし」とする。
- デバイス変更、切断、再接続、軸割当変更、リセットでセッションを更新し履歴を破棄する。アプリ内で既知のレポート破棄、無効値、パース失敗を差分の不連続境界とする。別Report IDに属していて今回含まれない軸は欠測とみなさない。無受信/状態不変100msだけでは不連続としない。長い間隔を埋める補間・複製はしない。
- バッファ上限は軸別W×10,000+1サンプル。8kレポート/秒の合成負荷で選択期間を保持できる量とする（実機レートを保証するものではない）。上限超過で窓内データを失った場合は警告と実際の保持時間を表示し、選択期間の完全な計測と扱わない。

## 平均ステップ精度: bit数の算術平均 v1

各軸の選択期間について、同一セッションで連続する有効サンプルから `d = abs(current - previous)` を求める。両端が窓内にある差分のみ採用し、ゼロ・非有限・範囲外・既知欠測境界を除く。

1. 各非ゼロ差分を `b = log2(2.0 / d)` へ換算する。有限の換算結果が得られる微小差分も採用し、qによる量子化は行わない。
2. **丸める前の各bの算術平均**を平均ステップ精度とする。差分そのものの平均をbit換算する方式や、ヒストグラムbinの中心値を平均する方式は使わない。
3. 表示時だけ小数1桁へ四捨五入する（`MidpointRounding.AwayFromZero`）。有効差分1件から表示し、軸ごと30件未満は参考値を付ける。
4. スティック全体はX/Yの有効差分を等しい重みで合算する。軸別平均を件数で重み付けするため、Xが8bitを1件、Yが10bitを3件なら9.5bit。片軸だけが有効な場合はその取得済み差分から平均を表示し、他軸の値は「—」とする。

例えば8bitと10bitの差分が各1件なら平均9bit。元差分の算術平均をbit換算した約8.68bitとは異なる。非ゼロ差分が0件なら「変化なし／ゆっくり動かしてください」。動かす速さや観測頻度で分布が変わるため、機器の公称bit数を保証しない。

詳細欄には平均bit数・有効差分件数・除外件数・保持時間等を表示する。`2^(1-平均bit)` と `2^平均bit` は平均bitからの換算値であり、前者は差分の幾何平均に相当する。算術平均差分と呼ばない。段階数が表現上限を超える場合は段階数を「—」にし、有限の平均bitは表示する。

実装方式IDは `mean_bits_v1`。最頻方式のコードは過去fixture・回帰検証用に保持するが既定registryから除き、旧保存設定 `modal_delta_v1` は平均方式へ移行する。[追加変更の設計](16-mean-precision-low-latency.md)参照。

## 震え度合い

各スティックのX/Yを別々に計算する。対象は現在の窓内の全有効サンプル（変化ゼロを含む）。平均 `mu = sum(v)/N`、母分散 `sum((v-mu)**2)/N`、母標準偏差 `sigma = sqrt(variance)`。旧Python版と同じ母標準偏差（分母N、ddof=0相当）とする。平均からの最大偏差は最大絶対偏差 `max(abs(v-mu))` とする。左右それぞれのX/Y軸について、「標準偏差」「平均」「平均からの最大偏差」の3指標を震え統計欄に並べて常時数値表示する。3指標はすべて同じ選択期間の窓（期間未満では取得済みの範囲）から計算する。標準偏差を差分列から計算しない。

左右それぞれにX/Yの2波形を表示する。横軸は現在を0、選択期間W秒前を−Wとする表示、縦軸は[-1,1]。現在の平均線と±sigma帯を軸別に表示し、色に加えて凡例と線種で識別する。別々のグラフまたは切替表示で帯が識別できること。拡大表示を付ける場合も倍率を明記する。欠落区間は線で結ばない。直近の標準偏差・平均・平均からの最大偏差の3指標に加えて、サンプル数・保持時間も数値で示す。

描画は横方向の表示幅に応じたmin/max間引きを使用し、短い揺れの山谷を保つ。計算には全サンプルを使う。意図した移動、ドリフト、ノイズはすべて位置のばらつきに含まれるため、静止して測る説明を画面に置く。

## 入力方式と比較の条件

HIDはReadFile完了、XInputはXInputGetStateのpacket番号変化を観測する。初回XInput状態は1回記録し、その後同じpacket番号の状態を繰り返し記録しない。固定1,000Hzの再サンプリングは行わない。同一時刻の複数レポートを受信順で保持し、時刻が同じという理由だけで破棄しない。時刻逆転は拒否する。ウィンドウ境界は受信時刻で判定し、軸ごとにサンプル数と保持期間を表示する。

震えの3指標は**受信サンプルを等しい重み**で計算する。XInputの状態更新検出や、値の変化時だけレポートが来る機器では、一定周期で測るPython版の統計と分布が変わる。時間重み付き統計や補間は初期版では追加しない。方式を追加する場合は名称と計算規則を別にする。

選択期間内に有効値がなければ統計は「データなし」。静止時の無受信を切断と断定せず、最後に受信した位置を示すときは「最終受信値」と年齢を付ける。X/Yが別レポートならそれぞれの年齢も確認できる。

HIDのBitSizeは格納幅であり、平均ステップ精度と別の情報。正規化は論理min/maxへの単一の線形変換とし、元整数値を保持する。例えば0..255ではstep=2/255、段階数255、約8.0bitとなる。結果を256に合わせるための補正はしない。

言語間の移植一致は、同じ正規化値・時刻・連続性を持つfixtureで比較する。実機のpygameポーリング値と新方式の観測列の時系列が同一になることは受入条件にしない。

入力方式/取得モードを変更したらepochと履歴をリセットし、異なる観測分布を混ぜない。XInputは状態全体の更新なのでボタンだけが変わった場合も各スティックの同値サンプルが生じる。XInputの格納幅やpacket更新数をセンサー精度/USBレポート頻度と読み替えない。

HIDとXInputの値はどちらも元整数と論理範囲を保持し、単一の線形変換で[-1,1]へ変換する。XInputのsigned16bitは[-32768,32767]を用い、正/負の領域で異なる係数を使わない。現在位置はXInputで「最終状態」、HIDで「最終受信値」と更新年齢を表示できる。選択期間中の状態不変で統計が空でも、XInput API成功による接続状態は別に維持する。

## 性能改善で維持する表示仕様（2026-11-01）

現在位置は最大60Hz、新しい解析世代の統計/推定/波形は最大10Hz、年齢・CPU等の診断は5〜10Hzで更新する。統計と波形を位置の更新周期に合わせて繰り返し構築しない。選択期間の計算区間、4軸の受信サンプル等重み、3指標を維持する。精度計算は後続指示により平均bit方式へ変更した。無受信時の時刻による期限切れを継続する。

描画点の省略と取得窓の保持上限を区別し、統計対象が失われていない場合に「選択期間未満の取得」と表示しない。解析が遅れた場合は計算対象時刻を表示し、現在位置は独立して更新する。具体的な改善契約・受入目標は[性能設計](07-performance.md)、実装済み範囲と未完了のWindows受入は[実装記録](09-performance-implementation.md)を参照。

## 1920×1080向けの配置（2026-11-01実装）

メイン画面は起動時に最大化し、左右の位置/精度と震え3指標/波形を有限Grid内に常時表示する。高DPI時は全体を同じ比率で縮小し、メインのスクロールを不要にする。推定詳細は別ウィンドウで最新値を表示する。計算/入力の意味は維持する。[配置・検証仕様](08-desktop-layout.md)参照。

## ステップ精度ヒストグラム（追加）

各取得時の隣接有効値の絶対差分を `log2(2/delta)` へ換算し、4軸合算・選択期間の1つのヒストグラムを表示する。bit数は小数1桁に四捨五入してから「8〜8.9」「9〜9.9」等の1bit幅で集計する。ゼロ・無効・欠測境界を除き、追加/期限切れで件数を更新する。[詳細](13-step-histogram.md)。
