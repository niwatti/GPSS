# 1920×1080向けデスクトップレイアウト

更新: 2026-11-01。メイン画面のレイアウト変更を実装した。性能改善R1〜R4とは別の変更で、計算・取得方式は変えない。

## 配置

Windowsの作業領域へ起動時に最大化する。タイトルバー/タスクバーを除いたクライアント領域を使い、メイン画面のScrollViewerを廃止する。

```text
┌──────────────────────────────────────────────────────┐
│ GPSS / スティックの位置・精度・震え       接続状態     │
│ 取得方式  コントローラー  低遅延固定  bit平均  操作ボタン │
│ 計測時間・頻度・CPU・欠落 / 入力診断                   │
├──────────────────────────┬───────────────────────────┤
│ 左スティック             │ 右スティック              │
│ 円と現在点 │ 精度/座標   │ 円と現在点 │ 精度/座標    │
│            │ 年齢/注記   │            │ 年齢/注記    │
│ 震え指標             X Y │ 震え指標              X Y │
│ 標準偏差・平均・最大偏差 │ 標準偏差・平均・最大偏差  │
│ 件数/保持時間            │ 件数/保持時間             │
│ X波形（平均/標準偏差帯） │ X波形（平均/標準偏差帯）  │
│ Y波形（平均/標準偏差帯） │ Y波形（平均/標準偏差帯）  │
├──────────────────────────┴───────────────────────────┤
│ 計測・推定上の注意                                    │
└──────────────────────────────────────────────────────┘
```

- 左右のカードは同じ幅。タイトル/操作/診断/注記はAuto行、カード領域はStar行で残りの高さを使う。
- 各カードは有限Gridで、上段に円と精度/現在値を横並び、下段に3指標のX/Y表と2つの波形を置く。固定360DIPの円と固定128DIPの波形を廃止し、割当高さに追従する。
- 3指標と波形は常時表示する。円は最低160DIP、波形は各88DIP以上を基準canvas内で確保する。
- 推定の詳細は「詳細…」から別ウィンドウを開く。表示中も最新の値へ追従し、メイン画面の高さを変えない。長い状態/診断文字列は省略表示し、ツールチップで全文を確認できる。

## DPI・リサイズ

WPFの寸法はDIPで扱う。基準となる最小canvasは1180×760DIP。通常は利用可能領域まで拡張し、表示倍率が高くクライアント領域が小さい場合は、canvas全体を同じ比率で縮小して収める。

```text
factor = max(1, 1180 / viewportWidth, 760 / viewportHeight)
canvas = (viewportWidth * factor, viewportHeight * factor)
Viewbox: Uniform / DownOnly
```

canvasの縦横比をviewportに合わせ、余白が過大にならないようにする。サイズ更新はSizeChanged時だけで、取得ごとにレイアウト要素を再構築しない。小さい画面/高DPIでは文字や円も縮小されるため、文字の読みやすさは実機で確認する。詳細・軸割当・取得設定の各ダイアログはメイン画面と別の領域として扱う。

## 検証

- 全体クロスビルドとWPF試験のコンパイルを行う。
- DashboardLayoutTestsに、1920×1080の100/125/150/200%相当のクライアント領域4ケースを追加。長い参考値/同率表示を含めてMeasure/Arrangeし、左右カード・円・3指標・2波形・ボタンの境界、波形の最低高さ、メインにScrollViewerがないことを確認する。
- この試験はDIPで有効領域を模したもので、実DPIのフォント描画・Windowsテーマ・タスクバー寸法を実測した試験ではない。macOSではWPF試験を実行できないため、Windowsでの実行と視覚確認を受入として残す。
- Windowsで最大化/復元/リサイズ、100/125/150/200%、長い機器名、切断/エラー、計測中の詳細表示を確認する。全要素がスクロールなしで見え、円/波形/文字が重ならないことを確認する。

性能問題の全量再解析・GC・過剰な再描画は[07](07-performance.md)の別段階で改善した。[09](09-performance-implementation.md)に実装と測定を記録する。今回のレイアウト変更だけで性能改善を受入済みとはしない。
