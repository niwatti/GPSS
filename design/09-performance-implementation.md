# 性能改善の実装と検証

更新: 2026-11-02。R1〜R3を実装した。R4は計測機構、非Windowsの回帰試験・仮想負荷・実時間モックまで実施。**Windows実機入力とWPF描画の性能受入は未完了**。報告条件のXInput / 通常 / 1,000Hzは、API呼出し数・状態更新数を分けて確認する。[元の調査・受入目標](07-performance.md)と[生ログ・再現手順](diagnostics/performance-optimized-2026-11-01/README.md)を併読する。

## 実装した処理

| 段階 | 変更 | 効果・維持する条件 |
| --- | --- | --- |
| R1 UI | 現在位置は最大60Hz、統計/波形は解析Revision単位、診断表示は5Hz。値が変わった要素だけ更新 | 同じ解析結果の繰り返し文字更新・Geometry生成を除去 |
| R1 描画 | 円/軸/目盛り/文字をサイズ・DPI・状態別にキャッシュ。波形Geometryを世代別に再使用し、resizeを100msで集約 | 非表示時の生成を止め、最小化中は表示Timerを停止。取得と解析は継続 |
| R2 現在位置 | 入力元のepoch付き最新4軸を、解析キューと独立した小さなimmutable状態として公開 | 解析が遅くても現在点は更新可能。切断/切替/リセットで旧epochを表示しない |
| R2 解析制御 | epoch取消、推定方式変更時の結果隔離、要求統合、worker専用再使用scratch | 取消済み解析の上書きを防止。UIへ可変バッファを共有しない |
| R3 震え | 固定容量ringと256点のCount/Mean/M2/Min/Maxブロック、segment tree | 境界ブロックだけ走査し、30秒全件のコピー・統計再計算を回避 |
| R3 ステップ | 差分edgeを追加/失効で更新し、最頻バケットの件数・補償和・順位を保持 | 差分作り直しとList/Sortを除去。ゼロ除外・同率・小数1桁丸めの仕様を維持 |
| R3 波形 | 絶対時刻の最大1024バケットに連続区間ごとのfirst/min/max/lastを保持 | 最大8192点/軸のimmutable描画投影だけを公開。上限時も全期間を保持する[追加修正](11-history-coverage-fix.md)とバケット全体の増分集計を導入。取得欠落と描画上限を別flagで表示 |
| R4 計測 | 排出/解析時間、キュー件数/byte/最古年齢、Revision、描画件数/時間、CPU/GC/割当のJSONL | 現場で原因を追跡するための記録。Windows性能の合格結果の代用にはしない |

30秒未満の窓・母標準偏差・平均・平均からの最大絶対偏差は元の観測を等重みで計算する。保持上限300,000点/軸と入力キュー8,192フレーム/16MiBは維持し、描画用の間引きで統計対象を減らさない。1920×1080向けのスクロール不要配置も維持した。

推定器は従来の `IStepEstimator` に加えて、任意実装の `IIncrementalStepEstimator` / `IStepEstimatorSession` を追加した。既定の最頻方式は増分sessionを利用し、将来のstateless方式はworker専用scratchの参照経路で動作する。方式変更時のsession再構築は1軸1回あたり約2msを目安に分割し、再計算中を表示する。同期拡張の単一Add/Estimateを強制中断する仕組みではなく、未対応推定器や未来時刻の参照経路にはO(N)処理が残る。

## 回帰確認

macOS 14.6.1 ARM64、8論理CPU、SDK 10.0.403 / runtime 10.0.14。全16プロジェクトをロック付き復元・クロスビルドし、警告0/エラー0。**130件実行・130件合格**（Core55、HID21、XInput12、Application29、CLI13）。WPF19ケースはコンパイル済み、Windows上のSTA実行は未実施。

- 増分結果を参照窓/計算器と比較し、保持上限、30秒の端、期限切れ、未来時刻、epoch、無効値、欠測、同率、極小分散、bit丸め境界を確認。
- 解析を意図的に停止しても最新位置が更新されること、切替後に旧方式/旧epochの結果を公開しないことを確認。
- 多数の連続区間を同じ描画バケットへ入れた場合の生成・失効・再生成と8192点上限を確認。
- 本番と同じJSONL writerを非WPF試験へリンクし、8行上限での破棄、書込み失敗、16MiB上限、稼働中flushと終了drainを確認。

記録: `TestResults/performance.trx`、`performance-build.log`、`performance-locked-restore.log`。上記はモック/計算の結果であり、WindowsのネイティブAPIや画面の受入件数へ加算しない。

## 10分相当の仮想負荷

4軸、解析10Hz、各600仮想秒。quantizedは256段階、random16は独立したsigned16値、mixedは1秒内に量子化/ランダム/状態不変が混在する。実コントローラーのノイズモデルではない。各ケースは直列実行し、WPF・入力API・実時間スケジュールは含めない。

| quantized / 1,000 | 0.297 / 1.526 / 7.270 | 4.66 | 99.08 → 98.67 | 30,001 / 2,271 |

解析時間は4軸の統計/推定/投影を含む。append時間は別計測で、生ログにp95/p99/最大を保存した。各6000回の解析を測定し、百分位保持数は最大10,000。割当は40秒以降の累積差を仮想時間で割った値であり、実行中の実秒あたりではない。生存ヒープは窓を生かしたままfull GCして測定した。これらの診断用GCは計測タイマーの外だが、仮想負荷のGC回数/停止合計には含まれる。

全9条件で取得保持/投影上限による欠落flagはfalse、最大240,001点/軸を保持した。データの少ない段階でも固定ringを事前確保するため、4軸の固定バッファは約94MiBを使用する。低レート時の生存メモリは旧版より増える代わりに、窓全件の繰り返し一時割当を抑える設計。差分辞書や描画の保持分は入力により増減する。仮想時刻40秒と600秒の2点比較だけで、Windows全体のメモリ安定性を受入済みとはしない。

## 実時間モックの前後比較

旧M6の正確なmanaged DLLを保全し、Random(608)で毎回4軸を変更する同じmock XInputをNormal/1msで実行した。旧版は40実秒、改善後は300実秒。取得レートはOSのスケジューリングにより異なる。改善後は表示snapshotを17msごとに読むが、WPFを描画しない。

| 35〜40秒の5秒区間 | 改善前 | 改善後 |
| --- | --- | --- |
| 実測状態更新/秒 | 776.9 | 842.6 |
| プロセス割当 | 265.43MiB/秒 | 8.89MiB/秒 |
| Gen2回収 | 100回 | 2回 |
| 区間GC停止合計 | 693.71ms | 70.07ms |
| CPU（1コア換算） | 32.74% | 16.72% |

この区間の割当は**96.65%減少**。同一Hzを固定した比較ではなく、画面の表示速度が同率で改善したことを意味しない。

改善後300実秒で259,411更新、平均864.6更新/秒。4軸解析は2923回の異なるRevisionを観測し、p95 **2.67ms** / p99 **20.93ms** / 最大 **26.56ms**。40秒以降の5秒区間の割当は **8.78〜9.00MiB/秒**（平均8.91MiB/秒）、全CPU比1.80〜2.29%。GC停止合計は2,241.48ms / 300.03秒（0.75%）。1回のGC停止p99は測定していない。

5秒時点で記録したキューは最大4件/2,048byte、最古年齢最大19.18ms、終了後は0件。区間内の最大滞留や既知破棄件数をこのログは直接記録していないため、全イベントで欠落0という受入には使わない。30秒窓充足後も解析対象は約10.4万点（4軸合計）で、割当と記録時点のキューに増加傾向は見られなかった。終了時の推定ヒープ143.64MiBはfull GC前の値で、生存ヒープとは区別する。

実時間モックのCPU/割当には入力・本体Controller・snapshot読出し・診断JSONLを含む。GUIや実APIのコストを含まないため、10MiB/秒のGUI込み目標を達成済みとはしない。実時間測定中はビルド/試験/他の負荷測定を同時実行していない。

## Windows用の診断と残る確認

```powershell
.\desktop\Gpss.Desktop.exe --performance-log C:\temp\gpss-perf.jsonl
```

JSONLは5秒ごと、8行のbounded queueを介して背景書込みする。既存ファイルへ追記し、合計16MiBで記録停止、行ごとにflush、終了時に残りをdrainする。queue飽和の破棄行数と書込み失敗を記録/表示し、入力経路を待たせない。最小化中も5秒ログは継続する。

UI/OnRender/Geometry/Timer遅延の分位点は直近256イベント。解析時間はworkerの測定、CPUは全論理CPU比、GC停止は区間合計、キュー値は記録時点の値。UI更新内・OnRender内にGeometry生成を含む場合があるので時間を単純加算しない。Timerの予定時刻からの遅れはDispatcher混雑の代理値で、ユーザー操作を処理するまでの待ち時間とは異なる。

Windowsで未確認なのは、実XInput/HID、WPFのMeasure/Arrange/描画、操作応答、観測→初回OnRender提出の遅延、GPU/DPI/リサイズ、GUI込みのCPU/割当/個々のGC停止、10分以上の定常実時間運転。現ログは観測→実際のOnRender提出時刻を直接突き合わせる計測を実装していないため、その受入には追加トレースが必要。R4の完了条件は[07](07-performance.md)を維持する。

GUI/CLIの新しい自己完結型win-x64配布物を生成した。依存lock16件が変わらないこと、GUI/CLI共有DLLの一致、EXEと主要ネイティブDLLのx64 PE、10.0.14ランタイムとライセンスを静的確認した。配布時には全ファイルSHA256とZIP CRCも照合する。旧版は `artifacts/GPSS-win-x64-before-performance.zip` と `GPSS-win-x64-M6-baseline.zip` に保全する。Windowsでの起動確認は別途必要。

配布生成時に一時SDK/NuGetキャッシュの一部消失を検出し、同じSDK 10.0.403をMicrosoft公式SHA512と照合して復旧した。依存はlock付きで復元し、GUI/CLIを直列publishした。復旧とpublishログも再現資料へ保存した。
