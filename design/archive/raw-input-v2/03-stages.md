# C#移行段階と受入条件

2026-10-28改訂。新計画は**M1〜M6**。旧Python版の段階1〜5とは番号を共有しない。旧段階1〜3の実装済み状態を、新C#版の完了扱いにしない。

現在は設計更新のみで、以下はすべて未着手。次にユーザーが「M3まで」等と指定したらM1〜M3を累積実装し、上限で停止する。実装済みと受入検証済みを分け、Windows未確認の項目は完了にしない。

| 移行段階 | 到達する状態 | 前提/完了判定 | 旧計画との関係 |
| --- | --- | --- | --- |
| M1 | C#構成・契約・HID取得可否を確定 | Windows Raw Input PoCを含む | 新規移行準備 |
| M2 | 解析・デモ・試験をC#移植 | 同一fixtureで数値一致 | 旧段階1と3の計算部分 |
| M3 | Raw Input/HID製品入力層と軸割当 | 実機で4軸取得、欠落/切断を検証 | pygame入力の置換 |
| M4 | WPFで位置・ステップ精度を表示 | 旧段階3相当のC# GUI | 旧段階2〜3のUI移植 |
| M5 | 震え3指標と最新30秒の図示 | 負荷/描画/計算の整合 | 旧段階4の新規実装 |
| M6 | CLI・配布経路をC#へ統一 | Python依存の廃止とWindows受入 | 旧段階5＋全面移行の完了 |

## M1: 構成と取得可否の確認

- [ ] .NET 10のソリューション、Core/Input.Abstractions/Application等の骨格、xUnit、SDK/依存固定。
- [ ] immutableモデル、IMonotonicClock、IInputSource、IStepEstimator、epoch/continuity/レポート時刻契約を確定。
- [ ] Python版のソース・data・テスト結果を復元可能に保全し、数値比較fixtureの形式を用意。
- [ ] Windows上の小さなC# PoCでRaw Input列挙/登録/WM_INPUT受信/Capabilities/4軸値を確認し、機種と接続方式を記録。
- [ ] 受信専用HWND、INPUTSINK、DEVNOTIFY、バックグラウンド受信と解除/終了を確認。

受入: CoreはWindows API参照なしでビルド/試験できる。Windows PoCで少なくとも1台のHID公開機器を読み取る。格納幅/論理範囲/Usageを記録し、機器ごとの制約を明記する。単にAPI宣言をコンパイルしただけで取得可否確認を完了扱いにしない。Windows/機器がなければ骨格と合成試験まで進め、PoCは未確認として次の実機依存項目に根拠なく進まない。

## M2: Core・デモ・試験のC#移植

- [ ] 軸別30秒窓、現在時刻による期限切れ、epoch/continuity、上限、既知欠落管理。
- [ ] 母標準偏差・平均・平均からの最大絶対偏差、最頻差分方式v1、registry、共通bit換算/表示。
- [ ] C#のFakeSource/デモ（左8bit/右10bit）、偽クロック、記録再生。
- [ ] Pythonの計算テストをC#へ移植し、言語間の同一fixture比較を行う。

受入: T-30ちょうどを含み古い点を除く。前端が窓外の差分、既知の欠測を跨ぐ差分を作らない。同tickの複数レポートは順序を保つ。軸が別Report IDで届くケースで値を複製しない。[-1,0,1]は平均0、標準偏差sqrt(2/3)、最大偏差1。8/9/10/11bitとstep=.003→9.4bit、四捨五入、ゼロ差分多数、同率、微小差分、最頻値の期限切れ、片軸未計測、推定器差し替えを検証する。

比較fixtureは正規化済み値/時刻/連続性を揃える。Raw Input固有の無受信/同tick/部分軸は新仕様の期待値を別途用意する。Python版にあった「固定1kHz/100ms超で差分を不連続扱い」の仮定を再現することは求めない。元の80試験を一対一で残す必要はないが、保全する振る舞いを試験対応表に記録する。

## M3: Raw Input/HID入力層

- [ ] 専用受信スレッド、メッセージループ、登録/解除、接続世代、bounded report queueと独立制御経路。
- [ ] RAWHIDの全dwCount処理、サイズ検証、受信時刻/順序、Preparsed DataとHID parser。
- [ ] signed/unsigned、Range/NotRange、Report ID/Link Collection、軸のNull/不正値の扱い。
- [ ] デバイス一覧と軸の生値・Usageを確認する最小診断UI。4軸割当/反転、未対応理由を表示。設定永続化はM6。
- [ ] 切断/選択変更/リセットで旧履歴を隔離し、受信無音と故障を分ける。

受入: Windows実機で左右4軸を受信し、割当と正規化を記録する。複数レポート/メッセージ、複数Report ID、signed境界、0..255/16bitの変換、32bitマーシャリング、キュー飽和、パース失敗はfixture/モックも併用して検証する。別軸の欠けたレポートを再サンプリングしない。バックグラウンドと抜き差しでフリーズ/リソースリーク/旧epoch混入がない。未対応形式を0値の正常機器として表示しない。

## M4: WPF位置・ステップGUI

- [ ] 左右の大きな円/現在点/X/Y値、画面サイズ/DPI追従、スクロール。
- [ ] X/Y別・左右代表の推定bit、方式名、基本ステップ差/段階数/件数/割合/同率/参考値の表示。
- [ ] デバイス選択、M3の軸割当UIの統合、リセット、計測期間、受信レートと軸別件数/保持時間。
- [ ] --demo起動、入力源差し替え、UI描画最大60fpsと計算10Hzの分離。

受入: C#デモが左8.0bit/右10.0bitと独立した点を表示。四隅を円周に投影しない。片軸無効時に代表値を出さない。実Raw Inputの受信から表示までをWindowsで確認。受信無音/30秒で統計が空/最終受信値の表示、切断、割当変更、リセットの整合を試験。UIの移動/リサイズ中も専用受信スレッドが進む。この段階では震えの表示とCSV保存はまだ不要。

## M5: 震え3指標と30秒グラフ

- [ ] 各スティックX/Yの**標準偏差・平均・平均からの最大偏差**を同時に常時数値表示。
- [ ] X/Y位置波形、平均線、±標準偏差帯、固定30秒横軸、欠測の空白、min/max表示間引き。
- [ ] 実際の軸別保持時間と件数、30秒未満/無データ/上限到達を表示。
- [ ] 高レート合成入力で負荷・窓更新・割当/GCを計測し、必要に応じて増分集計等へ最適化。

受入: 一定cなら標準偏差0/平均c/最大偏差0。既知系列・古いスパイクの期限切れ・開始直後・30秒無受信を確認。描画幅を変えても計算は変わらない。値変化時だけ届く系列は受信サンプル等重みで計算する。1k/8k reports/sを各5分再生し、メモリが上限で安定し、上限超過が可視化され、制御が応答する。解析p95<100ms、UIに100ms超の同期処理を持ち込まないことを目安に実測し、達しない場合は根拠と改善を記録する。実機レート保証と混同しない。

- [ ] 旧Python CLIの1軸選択、準備/開始、有限回数測定、標準偏差/平均/最大偏差出力、全軸CSV保存をC# CLIへ移植。

受入: 現行ソース/テスト/実行/ビルドにPythonが不要で、旧CLIの役割もC#で満たすこと。構成ファイルやXAMLまでC#へ変換する意味ではない。Raw Input非対応機器を別APIで取得したように見せない。GUI/CLIの起動と終了、既存CSV参照、配布物、対応機器と未確認範囲を根拠付きで記録。全受入前にPythonを削除しない。

## 旧段階からの対応

旧Python段階1〜3の実績は移植時の比較材料として利用する。旧段階4はM5、旧段階5はM6へ移し、旧構成固有の子プロセス・heartbeat・PyInstallerを再実装する必要はない。以降の進捗はM番号で管理し、[実装状況](implementation-status.md)に実装/自動試験/Windows実機の各状態を残す。
